## 2. 为什么和如何评测

最终答案正确不能证明执行路径可信。本阶段把每条用户可见声明与完整轨迹
对齐，并采用三层确定性规则：

1. 用冻结工具注册表检查工具是否存在、参数键和类型是否合法、调用状态是否
   允许。
2. 根据每条 D1 请求、已选选项和此前成功工具证据，检查参数值是否有来源；
   格式正确但无法推导的值仍判为参数幻觉。
3. 根据场景检查必要/禁止调用和偏序，并将库存、政策、工作流声明逐条关联到
   搜索结果、政策步骤或成功的交接工具。

另外向评测器注入 5 个合成缺陷，只验证规则能否检出，不计入 Agent 得分。

评测使用偏序约束，不要求所有场景共享唯一完整序列。例如：正常完成需要
`搜索去程 -> 搜索返程 -> 搜索酒店 -> 重验证 -> 生成交接链接`；需要审批和
无可行方案的案例必须停在搜索之后；搜索失败只允许已经发生的去程搜索；
重验证变更或失败不得继续生成交接链接。

## 10. 局限

1. 当前 0 工具幻觉的主要背景是工具选择由确定性编排器控制，不是模型开放
   选择工具。
2. 库存均为 Mock；参数真实性只相对于固定案例和 Mock 证据成立。
3. 影子幻觉仅评估结构化输出投影中的选中库存、政策和交接声明；没有覆盖
   任意自然语言中的隐含事实。
4. 每条只运行一次，不说明随机稳定性。
5. 合成变异证明了已定义错误可被检测，不证明未知错误类型都能被检测。
