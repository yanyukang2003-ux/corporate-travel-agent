# 实施路线图

## 已完成：框架基线

- 领域对象、状态机和关键不变量；
- Mock/Replay Provider 契约；
- 完整方案组合、可行性和政策引擎；
- 选择、审批、重验、重新确认与交接意图；
- 审计轨迹和核心回归测试；
- FastAPI 传输层。
- schema-bound OpenAI 适配器和模型调用元数据；
- 自然语言创建、跨轮字段合并和最多三轮澄清；
- Prompt Injection、相对日期、缺失字段和冲突场景测试。
- 每任务统一 12 次工具调用预算、调用记录、审计与安全终止态。
- 中英文城市别名标准化和无可行方案诊断。
- Provider 共享时钟和库存/交接有效期安全门。
- PostgreSQL/JSONB 任务聚合、事务审计、乐观锁、Alembic 和重启恢复。
- Provider 原始响应的内存/本地 WORM 对象存储、90 天默认保留期和读取策略。
- 内部试用登录、短期签名会话，以及员工、直属审批人和管理员资源授权。
- 城市、职级、酒店上限、例外规则和审批路径的严格外部配置与历史快照固定。
- 脱敏 Replay 数据集格式、WORM 导出器、完整性/路径校验、查询契约和整库去重统计工具。
- PreferTripPlan/Open-Travel 派生的 60 条工作流和 480 条中英文意图评测集、完整测试切分、固定来源哈希、许可追踪、适用维度计分及逐条离线执行器。

## 已完成：PostgreSQL 分阶段存储（A–D）

详见 `docs/postgres-operations.md`。

- **Phase A**：连接池环境变量、健康检查 `persistence_details`、生产禁止 AUTO_CREATE、运维手册、CI workflow  
- **Phase B**：任务投影列与索引、摘要列表/审批收件箱 API、`list_due_provider_retries` 调度查询  
- **Phase C**：政策配置与员工/政策快照入库、`POLICY_CONFIG_BACKEND=postgres`、导入脚本  
- **Phase D**：`outbox_events` 表与仓储、健康检查未发布计数  

## 下一阶段：达到可内部试用

1. 配置服务端 API Key，用 `examples/run_tool_loop_*` 对产品入口（工具循环）执行真实模型冒烟和质量评估（旧的 24 条意图冒烟随 legacy 入口删除，ADR-0003）；
2. 通过已完成的安全导出工具收集至少 20 个脱敏真实快照；当前 Mock 管道样例为 3 个，真实来源为 0/20；
3. 将现有派生评测校验结果汇总为安全、合规、可行性和澄清质量报告；
4. 正式部署前把本地 WORM 后端替换为启用 Object Lock 的 S3 兼容存储；
5. 正式部署前用企业 OIDC/SSO、MFA、集中吊销和网关限流替换本地认证；
6. 将审批/交接关键审计接入 Outbox 投递（邮件/IM），并完善多 worker 租约认领。

## V1.5：用户可见的浏览器辅助查询

- 仅由用户主动触发；
- 不保存账号密码，不绕过验证码，不做高频轮询；
- 人工确认可见结果后标准化并保存快照；
- 对页面文本按不可信输入处理，不能改变策略或状态机。

## 获得正式授权后

实现只读供应商适配器、凭证隔离、限流、超时、重试和实时冒烟测试。真实预订、支付、出票、退改签仍属于新的安全与业务验收阶段，不是当前框架的隐含能力。
