# 前端信息架构与页面覆盖

## 设计方向

前端服务于员工、直属审批人和审计/管理员三类角色。界面采用高密度、低干扰的企业工具
方向，并把路线、政策版本、库存时效与审计状态组织成一条“行程凭证带”，让使用者能在
首屏确认当前任务的关键证据。

## 页面覆盖

| 页面/界面 | 主要角色 | 覆盖能力 |
| --- | --- | --- |
| 智能规划 | 员工 | 自然语言需求、方案推荐、费用拆分、政策证据、选择、对比、重验提示 |
| 新建差旅 | 员工 | 自然语言创建、结构化输入入口、字段提示与数据边界说明 |
| 我的差旅 | 员工 | 本人任务列表、状态筛选、费用与任务编号 |
| 团队差旅 | 审批人 | 直属团队相关任务的只读状态视图 |
| 审批中心 | 审批人 | 审批队列、例外规则、申请理由、证据有效期、批准与拒绝意见 |
| 任务总览 | 管理员 | 全局任务、申请人、异常状态与运营指标的只读监控 |
| 差旅政策 | 全员 | 生效版本、员工等级、规则阈值、例外机制与内容指纹 |
| 审计与系统 | 管理员/审计 | 审计事件、哈希、库存/政策快照、Provider 状态、工具预算与安全边界 |

## 角色职责边界

| 角色 | 默认入口 | 导航 | 明确禁止 |
| --- | --- | --- | --- |
| 员工 | 智能规划 | 智能规划、我的差旅、差旅政策 | 团队审批、全局审计 |
| 审批人 | 待我审批 | 待我审批、团队差旅、差旅政策 | 新建/修改员工申请、系统管理 |
| 管理员 | 任务总览 | 任务总览、政策管理、审计与系统 | 冒充直属审批人批准或拒绝 |

同时拥有员工和审批人角色的账号合并两类职责。管理员角色采用独立运营工作区，不继承
直属审批人的决策入口；这一点与后端禁止管理员代替经理审批的规则保持一致。

任务详情复用同一页面框架承载状态变化：

- `DRAFT / NEEDS_CLARIFICATION / NEEDS_STRUCTURED_INPUT`：需求区与补充信息表单；
- `SEARCHING / PLANNING / WAITING_FOR_PROVIDER`：任务记录与进度/重试提示；
- `OPTIONS_READY / WAITING_FOR_USER`：方案列表、证据与选择；
- `WAITING_FOR_APPROVAL`：审批状态与只读方案；
- `REVALIDATING / RECONFIRMATION_REQUIRED`：价格重验与重新确认；
- `READY_FOR_HANDOFF / HANDED_OFF`：官方平台交接与完成确认；
- `PROVIDER_FAILED / NO_FEASIBLE_OPTION / TOOL_BUDGET_EXHAUSTED / OUT_OF_SCOPE`：
  失败原因、可恢复操作或安全终止说明。

## 当前实现边界

页面主体当前使用本地演示任务，适合独立评审信息架构、视觉层级与交互。联调基础已完成：

1. `GET /trip-tasks/{task_id}` 的方案对象返回结构化交通段、酒店、库存引用、可行性、
   时长和评分字段，前端 TypeScript 类型与其保持一致。
2. API 客户端默认访问 `/api`，Vite 开发服务器将其代理到 `127.0.0.1:8000`。
3. 应用入口已挂载 `AuthProvider`：认证关闭时使用开发身份；认证开启时展示登录页；401、
   会话过期和主动退出都会清理本地令牌。审批和审计导航按照角色显示。

仍待后续联调的是把主页面的演示任务替换为 `listTasks/getTask` 的真实返回，并为审批决定、
重新规划、价格重验和交接等变更操作补充提交中禁用、确认与服务端错误状态。

## 响应式与可访问性

- 桌面端为固定侧栏 + 任务内容 + 决策栏；平板收窄侧栏；手机改为底部导航与单列布局。
- 关键输入、图标按钮和模态框均提供可访问名称，键盘焦点使用清晰描边。
- 未引入外部图片或图标依赖，首屏不依赖远程资源；SVG 图标继承文字颜色。
