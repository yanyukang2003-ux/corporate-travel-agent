## 2. 为什么和如何评测

完成任务不代表路径高效。本阶段对每次调用分别检查：

1. 无效调用：工具、参数或调用状态违反阶段 3 的冻结契约。
2. 重复调用：工具名、参数哈希和输入状态相同，且两次调用之间没有新增证据、
   状态变化、用户输入、政策结果或可操作错误。
3. 无信息增益：没有新增证据、状态变化、安全重验证、交接产物或可操作错误。
4. 冗余调用：无效、无增益、无合理理由的重复，或超出场景最小路径数量的调用。
5. 路径效率：实际工具序列必须精确匹配场景最小路径；另统计调用数分布和预算。

冗余采用规则化的最小路径反事实，没有真的删除调用并重新执行 Provider。对个人
项目而言，这种方式成本低、稳定、适合持续回归；局限在第 10 节单独说明。

## 7. 最小路径定义

- 正常完成：去程搜索 → 返程搜索 → 酒店搜索 → 重验证 → 创建交接链接。
- 需要审批或无可行方案：三类搜索后停止。
- 重验证发生变化或失败：三类搜索 → 重验证，禁止创建交接链接。
- 首次搜索失败：只保留已经失败的去程搜索。

阶段 3 使用偏序检查“先后关系是否正确”；本阶段进一步要求实际工具序列与
最小路径精确相等，因此额外重复一次合法调用也会导致路径效率失败。

## 11. 局限

1. 调用来自确定性编排器，天然比开放式模型规划更容易得到最小路径。
2. 冗余判定基于冻结场景契约，没有执行真实的逐调用消融实验。
3. Provider 返回体只保留哈希和证据引用；未被轨迹结构化的信息增益无法复原。
4. 当前没有自动重试轨迹，尚未验证“合理重试不应被判为重复”的真实样本。
5. 本阶段不评价 Token、真实网络时延或接口费用。
